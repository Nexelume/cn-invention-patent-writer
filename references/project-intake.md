# Project intake and source triage

Use this reference when the input is a project folder, paper/code bundle, engineering design, experiment archive, or mixed technical material.

## Intake record

Record, when available: jurisdiction and intended filing type; applicant-side title, terminology, inventors, applicant, and template; source paths and file types actually inspected; execution or experiment entry points and relevant versions; data provenance, dates, seeds, baselines, and measured outputs; requested deliverable and read-only or write scope.

Do not infer inventor, applicant, priority, production deployment, or achieved effect from filenames or directory names.

## Triage order

1. Read README, project notes, existing patent drafts, and template labels.
2. Identify the authoritative implementation or technical description and its interfaces.
3. Separate source evidence from plans, comments, claims, and generated artifacts.
4. Run the problem and material check below before treating an idea as an applicant-supported invention. Use active discovery to develop provisional problems and mechanisms even when the drafting check cannot yet pass.
5. Ask only for facts that materially change the problem, mechanism, claim scope, or requested deliverable.

## Problem and material check

Record the following before screening a candidate as an applicant-supported invention:

1. **Problem:** What technical object is affected, under what operating condition, and where does the current method fail or fail to meet a concrete design constraint? What observation or comparison would show the difference? Avoid starting with a chosen solution (for example, “use AI”). If an observation has several possible causes, distinguish what is observed from what is inferred.
2. **Support:** Cite the supplied observation, failure example, design requirement, drawing, interface, code, or record that grounds the problem and constrains possible mechanisms. A user-confirmed design objective plus enough technical detail to trace a proposed mechanism can suffice without a prototype or measured result. Public literature can suggest hypotheses and baselines; it is not evidence of an applicant's own implementation or observed results.
3. **Decision:** Continue to screening a chain for drafting only when the problem and enough material to outline a technically grounded chain are clear from the source or confirmed by the user. If only a broad direction is known, relevant material is absent, or an unresolved choice would lead to different main mechanisms, use [active invention discovery](idea-discovery.md) and keep its results provisional. First investigate what can be established from existing context and public sources; then state what is known, ask only the questions that materially distinguish alternatives, and suggest the smallest feasible check. Do not represent an exploratory hypothesis as the applicant's mechanism, draft a disclosure or filing text, or present a proposed check as performed. Reassess when the missing evidence or decision arrives.

Use this check for mining, substantive drafting, or a revision that changes the technical spine. It does not prevent a standalone search, audit, or mechanical check within its stated scope; report any limits imposed by missing information.

## Evidence labels

Use exactly one label for each material assertion: verified fact, prior-art fact, proposed implementation, design parameter, acceptance criterion, or unknown. Keep measured, calculated, exploratory, training, calibration, and historical results distinct.

## Intake output

Return a compact source inventory, the problem and material decision with its basis, and the proposed next mode. List grounded candidate chains when screening for drafting is supported; otherwise return the discovery findings, missing information, focused questions, and a minimal verification suggestion. Intake does not authorize training, production execution, remote access, downloading, filing, or external communication.
